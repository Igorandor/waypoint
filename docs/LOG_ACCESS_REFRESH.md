# Log capture after access loss

A successful log capture previously remained readable and exportable after a refresh of the same source returned HTTP 403. Browser reproduction with synthetic protected lines confirmed the error banner, retained line and enabled export in the actual production component before this fix.

The current request now discards captured evidence belonging to the denied source. This includes a matching previous observation and, when the current capture is removed, its embedded bookmarks and notes, selected context and notice. With no current capture the investigation export is disabled. A denial for alerts does not discard an existing messages capture. A transient HTTP 500 or network failure retains the last observation. These rules do not change the server's authorization checks or revoke files already exported by the operator.

The native-file selector remains disabled while a request is pending. The existing request sequence check still gates failure handling. Selecting another source while idle does not relabel the existing capture: its heading and export keep its own observed source until a successful new capture replaces it.

Four offline regression tests exercise the same source-specific evidence transition used by the component: denial of both captures, transient failures, denial of a different source and independent current/previous source matching. They do not replace browser verification of controls and downloads.
